## 3. 通用约定

### 3.1 协议与编码

- **协议**：HTTPS
- **编码**：UTF-8
- **数据格式**：JSON（如有表单/URL-ENCODED 请注明）

### 3.2 幂等与重试

- **幂等键**：建议使用 `request_id` / `order_id`（需全局唯一）
- **重试策略**：网络超时可重试；业务失败不重试（按接口说明）
- **重复请求处理**：返回相同业务结果/同一订单状态

### 3.3 时间格式

- `yyyy-MM-dd HH:mm:ss`（示例：`2026-04-27 15:30:00`）或 ISO8601（请二选一固定）

## 4. 鉴权与签名

> 如 HOMO 使用签名，请在此给出明确算法与字段规则。

- **签名算法**：HMAC-SHA256 / RSA2 / MD5（择一）
- **签名字段**：请求体字段排序规则、是否包含空值、是否 URL 编码
- **请求头**：`X-App-Id`、`X-Timestamp`、`X-Nonce`、`X-Signature`（示例）
- **验签失败**：错误码与返回体

## 6. 接口明细模板

### 6.1 接口名称（示例：创建订单）

- **方法**：POST
- **路径**：`/api/v1/order/create`
- **说明**：-

#### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| request_id | string | Y | 幂等号 |
| order_id | string | Y | 我方订单号 |
| amount | number | Y | 金额（单位：分/元，需明确） |

#### 响应参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| code | string | Y | 返回码 |
| message | string | Y | 返回信息 |
| data | object | N | 业务数据 |

#### 示例

请求：

```json
{
  "request_id": "20260427-0001",
  "order_id": "ORD202604270001",
  "amount": 100.5
}
```

响应：

```json
{
  "code": "0",
  "message": "ok",
  "data": {
    "channel_order_id": "CH202604270001"
  }
}
```
