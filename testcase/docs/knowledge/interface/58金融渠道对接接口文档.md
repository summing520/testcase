## 38.请求加解密

加解密及签名验签

58会提供签名验签加解密工具jar包，若机构同为java环境，可直接使用，以下内容供参考。

加密验签及哈希算法

- 对称加密：AES  秘钥16位; 每次请求随机生成

- 非对称加密：RSA ; 58提供公钥给机构，机构提供公钥给58

- 哈希算法为：SHA256

排序规则

-请求参数排序

- 对公共请求参数中appId、productId、uid、_t、key以及密文业务参数params，根据字母ASCII码顺序对参数名称进行排序。例如：排序后的字符串为_t=154701522605&appId=1234567adfa8&key=xxxx¶ms=xxx&productId=9999&uid=xxx2。

- 将排序好的参数名和参数值按照key1=value1&key2=value2的方式拼接，拼接后的字符串即为待签名字符串。拼装好的字符串需要采用utf-8编码。

- 排序后的请求字符串即为待签名字符串

-响应参数排序

- 对公共响应参数中code、msg、key、业务参数密文data，根据字母ASCII码顺序对参数名称进行排序。例如：排序后的字符串为code=0&data=xxxx&key=xxxx&msg=xxx。如果data为空则data与key不参与排序，即排序后的字符串为：code=0&msg=xxxx。

- 排序后的响应字符串即为待签名字符串

加密签名流程

变量约定

- orgpri：机构私钥

- orgpub：机构公钥

- 58pri：58私钥

- 58pub：58公钥

- requestBizData：请求的业务参数，JSON字符串

- requestSortedParams：排序后的请求参数，等待加签的content，见请求参数排序，类型为字符串

- responseBizData：响应的业务参数，可以为空，类型为字符串

- responseSortedParams：请求排序后的响应参数，等待加签的content，见响应参数排序，类型为字符串

机构调用58接口

- 机构侧加密签名流程

- 随机生成16位字符串作为AES秘钥（planKey）

- 对AES秘钥用58公钥加密：key = RSAEncrypt(58pub,planKey)

- 加密业务参数: params= Base64(AES(planKey, requestBizData))

- 对请求参数进行标准排序得到requestSortedParams，即为待加签的文本content

- 对content用机构私钥加签；sign = Base64(RSAEncrypt(orgpri, SHA256(content)))

- 封装HTTP请求报文{"appId":"xxx","productId":"xxx","_t":1564059097667,"key":key,"sign": sign,"params": params
}

- 58侧验签解密流程

- 对请求参数进行排序requestSortedParams, 即为待验签文本content

- 用机构公钥验证签名：RSAVerify(orgpub, sign, SHA256(content))

- 解密对称秘钥 planKey = RSADecrypt(58pri,key)

- 解密业务参数密文 requestBizData = AESDecrypt(planKey,data)

- 业务处理

- 如果responseBizData非空,进行加密签名操作；否则进行签名操作

- 随机生成16位字符串作为AES秘钥（planKey）

- 对AES秘钥用机构公钥加密：key = RSAEncrypt(orgpub, planKey)

- 加密业务数据: data = Base64(AES(planKey, responseBizData))

- 对参数进行标准排序得到待加签的文本content

- 对content用58私钥加签；sign = Base64(RSAEncrypt(58pri, SHA256(content)))

- 封装HTTP响应报文为

{
    "code":code,
    "msg":"xx",
    "key":key | null,
    "sign":sign,
    "data":data | null
}

58调用机构接口

- 58侧加密签名流程

- 随机生成16位字符串作为AES秘钥（planKey）

- 对AES秘钥用机构公钥加密：key = RSAEncrypt(orgpub, planKey)

- 加密业务参数: params= Base64(AES(planKey, requestBizData))

- 对请求参数进行标准排序得到requestSortedParams，即为待加签的文本content

- 对content用机构私钥加签；sign = Base64(RSAEncrypt(orgpri, SHA256(content)))

- 封装HTTP请求报文{"uid":"1234abcd","appId":"xxx","_t":1564059097667,"key":key,"sign": sign,"params": params
}

- 机构侧验签解密流程

- 对请求参数进行排序，得到标准content

- 用58公钥验证签名：RSAVerify(58pub, sign, SHA256(content))

- 解密对称秘钥 planKey = RSADecrypt(orgpri, key)

- 解密业务参数密文 requestBizData = AESDecrypt(planKey,data)

- 业务处理

- 如果responseBizData非空,进行加密，签名操作；否则进行签名操作

- 随机生成16位字符串作为AES秘钥（planKey）

- 对AES秘钥加密：key = RSAEncrypt(58pub,planKey)

- 加密响应业务参数: data = Base64(AES(planKey, responseBizData))

- 对响应参数进行排序，生成responseSortedParams，即待加签的content

- 计算responseSortedParams哈希值；hash = sha1(responseSortedParams)

- 用orgpri对content签名；sign = Base64(RSAEncrypt(orgpri,hash))

- 封装HTTP响应报文为

{
  "code":code,
  "msg":"xx",
  "key":key | null,
  "sign":sign,
  "data":data | null
}

### 4.授信-用户授信标准推送

用户授信标准信息推送(机构提供)

1. 接口调用场景

当用户查看合作机构的产品，并提交基础信息和抓取信息后，58金融将判断是否符合机构的要求，若用户符合机构要求，将会生成订单，并调用合作机构提供接口。

2.接口简单说明

58金融调用订单信息推送接口，将用户填写的信息等推送给合作机构。接口参数中包括订单的基本信息、申请人填写的基本信息、抓取信息等。机构获取到订单信息后可自行做一些处理，例如生成机构对应订单、注册机构用户等。最终合作机构返回推送结果给到58金融。

3.接口调用说明

- 接口提供方：合作机构

- 请求方式：HTTP POST

- 数据类型：JSON

- 请求地址：

- 接口类型：同步

- 性能要求：5s，超过5s后判断为超时。超时后会重新进行3次重试调用。间隔为1分钟调用。

- 幂等性要求：重复请求，机构需返回相同结果。（由于可能出现网络超时，我们没有收到机构返回的结果，我们会重推数据，若您返回失败，会导致用户无法完成后续操作）

建议：由于推单成功率会直接影响用户后续流程，因此希望机构及时响应，接口仅做接收请求操作，将下载数据等复杂操作异步处理。

### 8.绑卡接口(机构提供)

绑卡接口

1. 调用场景

- 绑卡阶段，用户选择新绑定银行卡

- 绑卡阶段，用户选择已绑定银行卡

2. 绑卡方式介绍

58金融不支持绑卡操作，需要机构完成绑卡操作。

用户在58金融可选择绑定已有的银行卡（58金融通过拉取用户已绑银行卡接口获取），也可选择绑定新的银行卡。

目前58金融支持2种绑卡方式，合作机构可以根据自身情况进行选择：

不同绑卡方式的适用场景：

- 合作机构需要通过58金融绑卡页面绑卡 ：查看方式2：验证码绑卡的详细介绍

- 合作机构需要跳转到自身提供的绑卡页面进行绑卡，用户需在58金融填写相关信息，跳转到机构提供的自身绑卡页面，会默认填写用户之前在58金融填写的参数：查看方式1：跳转机构提供的第三方页面绑卡的详细介绍

3.方式一  验证码绑卡

3.1 接口调用流程

- 用户进入绑卡页面，58金融调用机构提供的银行卡列表接口，获取银行卡列表信息。

- 根据用户的操作不同，后续流程不同用户选择已绑定的银行卡，此时无需发送验证码58金融调用机构提供的绑卡接口，告知机构用户选择的银行卡。机构返回code=0后，我方则认为绑定成功。用户选择新绑定银行卡58金融调用机构提供的绑卡接口，将用户填写的用户名、手机号、银行卡号、开户行、开户行地址、身份证号、回调地址等信息提交给机构。机构接收信息处理，并发送验证码给到用户，并告知58金融处理结果（是否发送了验证码）。注：若机构对接了银行卡列表接口，机构只能对新绑卡发送验证码，已有银行卡无需发送验证码。若用户未收到验证码，58金融支持用户操作重发验证码，58金融将重新调用机构绑卡接口。用户在58金融平台填写验证码，58金融调用机构提供的接口发送验证码给到机构。机构接收验证码处理绑卡，并告知58金融数据是否接收成功。随后，当成功接收到58金融的请求且绑卡流程完成后（包含无需发送验证码的情况），机构需要异步调用58金融提供的接口告知绑卡结果。我方会根据绑卡结果反馈接口的结果更新最终的绑卡结果。接口链接：绑卡结果反馈接口
